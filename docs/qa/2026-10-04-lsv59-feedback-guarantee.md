# LSV59 reading feedback and La-back guarantee

## Reviewed scope

Feedback belongs to real displayed reading parts: owned palace narratives, four attached identity excerpt sections, visible legacy narratives/reflection/action groups with actual chart context, authorized free opening text and deterministic signal descriptions. Guest placeholders, locked/absent text, geometry and evidence navigation do not gain paid controls. Palace telemetry uses each palace's actual SKU. Related links accept only existing canonical palace suffixes and preserve VI/EN chart routes.

An in-memory localized root notice keeps an approved refund result and related action after immediate reader revocation or daily-reader removal. It captures the initiating verified non-anonymous account, rejects delayed callbacks from a different current account, hides while session identity is pending and clears on logout/account change. It never persists financial results. A report-scoped not-found boundary retains that layout while missing, foreign and revoked reports still receive a uniform 404; it exposes no report data or new route. Print excludes feedback and refund notices.

## Evidence and gates

- Required `pnpm i18n:check`, `pnpm lint`, producer-rebuilding `pnpm typecheck` and production build must pass at the accepted head.
- Reader/free-preview focused checks verify projected ownership, actual chart authority, guest opening exclusion and missing content.
- Existing PostgreSQL guarantee tests use an injected frozen clock and verify atomic restore/revoke, idempotent replay, first-account claim/concurrency, rollback, the exact 24-hour boundary and the price limit.
- Isolated feedback browser checks cover VI/EN, successful explicit claim, replay-key preservation on failed retries, malformed replies and print exclusion. A React/browser race reproduces A's delayed response after B's refund and proves B's result/action survives; pending identity, logout and dismissal are verified.
- Fourteen real-network flows cover the existing six funnel paths plus a guarantee path at 390/1440px. The new path uses supported signup/verification/signin, trusted synthetic funding, a real 120-La purchase and receipt-bound synthetic stored reading. It submits actual HTTP feedback/claim, restores both original wallet buckets, returns the same claim/receipt on replay, refuses another key, removes the revoked reader, retains the approved result, clicks its real related-palace dialog after revocation, denies the revoked report and exercises English free-feedback navigation.
- The guarantee browser clock is frozen near the actual server time. Correct-SKU `part_feedback` and `guarantee_claimed` rows must persist through the real ingress; report/chart identifiers must be absent from their properties. Other fixed-time funnel paths make no full telemetry-delivery claim.

The isolated QA setup waits for API liveness before the first verification send. Intentional unused Redis remains; listener availability is not full production readiness. Earlier fixture runs demonstrated a cold-start refused connection, and the initial guarantee run demonstrated the global-404 notice loss. Those failures are retained outside Git and corrected rather than treated as acceptance.

## Release closure

Exact-head independent GO, CI, immutable image deployment, strict runtime readiness/worker health, protected operator file equality and published-image real-network proof are required before Kaneo Done. Evidence and credentials stay outside Git in restricted private directories; only owned fixture containers/networks are removed. No bank transaction, provider call, real-recipient message, generated PDF, AI quality or revenue claim is made by this acceptance.
