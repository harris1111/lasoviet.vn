# The 12 palaces in a Tu Vi chart

## What this page can establish

This article explains twelve palaces from the versioned implementation boundary. the contract defines twelve canonical palace identifiers and requires each identifier to be unique in a normalized chart. It does not attach a traditional personality meaning to the identifiers. It does not add traditional interpretation that is absent from the repository sources.

## Independent example

The fixture manifest checks palaceCount equals 12. A useful inspection is to count the normalized palace entries and confirm that soulPalaceId and bodyPalaceId point to entries in that list.

## Figure specification

Figure 4: a twelve-slot grid labelled only with canonical palace identifiers and arrows from soulPalaceId and bodyPalaceId. The figure is an explanatory diagram, not a generated natal chart and not an instruction to make a personal decision.

## Limits

The current application uses iztro 2.6.0 with ziwei.default, preserves input precision and warnings, and records documented gaps. It does not independently validate true-solar-time correction, every school variation, or traditional meanings outside the mapped fields.
