# How a Tu Vi chart is built

## What this page can establish

This article explains chart construction from the versioned implementation boundary. the adapter receives normalized calendar and time input, then maps raw iztro fields into canonical identifiers. The public method is pinned to iztro 2.6.0 and ziwei.default. It does not add traditional interpretation that is absent from the repository sources.

## Independent example

At 23:30 the late-Zi fixture uses adapter timeIndex 12, while the early-Zi fixture at 00:30 uses timeIndex 0. The example demonstrates input handling rather than a personal forecast.

## Figure specification

Figure 2: a two-row fixture table comparing early-Zi and late-Zi input times, adapter indices, and recorded limitations. The figure is an explanatory diagram, not a generated natal chart and not an instruction to make a personal decision.

## Limits

The current application uses iztro 2.6.0 with ziwei.default, preserves input precision and warnings, and records documented gaps. It does not independently validate true-solar-time correction, every school variation, or traditional meanings outside the mapped fields.
