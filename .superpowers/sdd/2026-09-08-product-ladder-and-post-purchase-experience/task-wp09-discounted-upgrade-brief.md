## Binding Rules

- Tier-1 price is exactly 19,000 VND.
- Tier-2 list price is exactly 79,000 VND.
- Upgrade credit equals the actual amount paid on an unrefunded paid Tier-1
  order for the same owner and chart.
- Credit expires exactly seven days after Tier-1 `paid_at`.
- Eligibility is `now < credit_expires_at`; at the exact expiration timestamp
  the full 79,000 VND price applies.
- Tier-1 purchase UI must disclose the seven-day limit before payment.
- Upgrade unlock reuses the report generated by WP-08 and must not enqueue a
  second AI generation.
- English orders remain on V2; the 19k offer remains Vietnamese-only.

## Database And Migration

Add to `commerce_orders`:

- `price_variant text`
- `credit_applied integer not null default 0`
- `credited_from_order_id uuid` self-reference to `commerce_orders.id`
- `credit_expires_at timestamp with time zone`

Migration requirements:

1. Existing Tier-1 rows get `price_variant = '19k'`.
2. Existing paid Tier-1 rows get
   `credit_expires_at = paid_at + interval '7 days'`.
3. Existing rows get `credit_applied = 0`.
4. Add focused checks preventing negative credit and inconsistent discounted
   upgrade rows.
5. Do not mutate invoice numbers, SKU identifiers, historical charged amounts,
   entitlements, or report content.

For new rows:

- Tier 1 stores `price_variant = '19k'`.
- A discounted Tier-2 order stores the applied credit, source Tier-1 order ID,
  and the source credit deadline as its immutable pricing snapshot.
- A full-price Tier-2 order stores zero credit and no credited source.

## Server Pricing

Under the existing chart-wide transaction lock:

1. Resolve an eligible source order only when it is:
   - same owner and chart;
   - SKU `ZIWEI-NATAL-EXCERPT-P0`;
   - status `paid`;
   - not refunded;
   - same locale;
   - has non-null `paid_at` and credit expiration;
   - `now < credit_expires_at`.
2. Credit is the actual Tier-1 charged amount, capped at the Tier-2 list price.
3. Net amount is `max(79,000 - credit, 0)`.
4. Persist the exact amount and credit fields when the Tier-2 order is created.
5. Pending-order reuse must preserve the original quote only while both its
   normal TTL and credit deadline remain valid.
6. At or after the credit deadline, expire the discounted pending order and
   create/reuse a full-price order with zero credit.

Payment enforcement:

- When Tier 1 becomes paid, set `paid_at` and
  `credit_expires_at = paid_at + 7 days` in the same transaction.
- A discounted Tier-2 order paid or self-claimed at/after its credit deadline
  must not create payment success, entitlement, reservation, or report unlock.
  The existing unmatched-payment flow handles received funds.
- Standard late-payment behavior remains unchanged for orders without expired
  upgrade credit.
- Preserve WP-08 same-locale one-report reuse.

Payment instructions:

- For a discounted pending upgrade, `expiresAt` is the earlier of normal order
  TTL and the stored credit deadline.
- Other orders retain the existing TTL behavior.

## Customer Projection And UI

Expose only customer-safe pricing facts required by the selector:

- charged/order amount;
- applied credit;
- credit expiration timestamp.

Never expose `credited_from_order_id`, SKU identifiers in rendered/browser
state, provider IDs, or technical pricing metadata.

The authenticated selection page must load owner-scoped order history along
with the library. If pricing history is unavailable, fail closed for purchase
actions rather than display a potentially wrong upgrade quote.

Vietnamese UI requirements:

1. Before Tier-1 payment, show a concise disclosure that the 19,000 VND amount
   is credited toward the comprehensive report for seven days from payment.
2. With eligible Tier 1, the Tier-2 offer shows:
   - list price 79,000 VND;
   - applied credit 19,000 VND;
   - net price 60,000 VND;
   - exact expiration date/time;
   - concise names of the newly unlocked sections.
3. At/after expiry or after refund, show full 79,000 VND and no applied credit.
4. When Tier 2 is owned, never render the Tier-1 offer.
5. After upgrade, the Tier-2 read/progress action resolves the existing
   same-chart report created for Tier 1.

Use existing layout/classes where practical. Do not add marketing disclaimers,
AI disclosure, confidence labels, methodology text, or unsupported claims.

## Required Tests

Use injected/frozen clocks. Prove:

1. Tier-1 payment persists deadline exactly `paid_at + 7 days`.
2. At `paid_at + 7 days - 1 ms`, Tier-2 order is 60,000 VND with 19,000 VND
   credit and source/deadline fields.
3. At exactly `paid_at + 7 days`, Tier-2 order is 79,000 VND with zero credit.
4. Refunded Tier 1 gives no credit.
5. Credit uses actual Tier-1 paid amount and floors net price at zero.
6. A discounted pending order expires at the credit deadline, is not reused,
   and its replacement is full price.
7. A webhook or self-claim arriving at/after the discounted deadline creates no
   entitlement/unlock and is retained through the unmatched-payment behavior.
8. Payment instructions cap expiry at the credit deadline.
9. Same-locale eligible upgrade creates two entitlements but remains one report
   reservation and one generation outbox event.
10. UI shows 79k - 19k = 60k and exact deadline before expiry; full 79k at the
    exact deadline and after refund.
11. Tier-1 card contains the mandatory seven-day pre-payment disclosure.
12. Owned Tier 2 hides Tier 1 and resolves the existing report action.
13. No rendered/serialized browser output contains `ZIWEI-*` or credited source
    IDs.

Run focused tests only, then builds/typechecks in producer-to-consumer order,
web production build, and `git diff --check`. Return changed paths and exact
results. Stop with `BLOCKED` or `NEEDS_CONTEXT` if work exceeds one direct
correction.
