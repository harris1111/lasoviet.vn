# LSV79 durable recovery attribution

## Bounded brief

Implement the already approved phase08 reminder-to-payment attribution under FD081/085 and the FD112 capture-only boundary. An opaque random delivery ID carried in the canonical checkout link fragment identifies the exact reminder. Bare UTM parameters, guessed order IDs and payment navigation never establish attribution. A private POST persists an idempotent receipt only for a verified owner, current offers consent/preferences, exact active chart/version, pending unexpired order and its immutable continuation/intent. Capture links create a separate captured-click classification and can never become customer recovered revenue. The client removes the fragment and records only a receipt; it never confirms payment, creates an order, grants or spends La.

Independent review found that existing payment events do not durably identify production versus sandbox or disabled-provider origin. Therefore this slice implements receipt/captured-click attribution only and fails closed for monetary attribution. No worker may infer production provenance from the current runtime flag or payment timestamp. The dashboard exposes captured/sent/eligible-click counts separately and explicitly reports monetary attribution as unavailable until a future bounded payment-provenance change has independent review and published acceptance. Captured classification remains immutable even if delivery status later changes; each order has at most one receipt. Official purge removes receipts before notification captures; retained financial records are unchanged.

Scope: strict receipt contract, one private receipt table/migration, backend receipt service, existing private commerce controller/BFF, invisible checkout receipt component and canonical route-registry entries; capture link and focused frozen-clock PG/HTTP/component tests; dashboard runbook. No SMTP, provider activation, production environment edits, free-chart teaser, new pricing or customer email cohort. Full LSV79 remains In Review while free-chart follow-up, placement and outbound acceptance are held.

Release gates: rebuild changed dist producers; focused PG/HTTP/browser and existing recovery regressions; i18n/lint/typecheck; exact-head independent review, CI, master merge/deployment, isolated published-image receipt/capture/purge acceptance. Production default remains disabled/capture-only as already configured. No monetary projection or source backfill is implemented in this slice.
