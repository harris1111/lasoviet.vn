# LSV60 subscription verification

The phase07 opt-in request is implemented as an additional subscription to an immutable owned report. Automatic transactional messages remain independent. The server supports only `REPORT_READY_SUBSCRIPTION_MODE=disabled|capture`; missing or unknown values disable registration and scanning. Production environment values are unchanged, so the UI remains hidden and the private API returns disabled after authorization. Capture mode never calls an SMTP adapter or adds a sendable delivery row.

The database enforces one subscription per owner/version, reservation lineage, locale/status constraints and a positive state version. Capture scans least-checked subscriptions first; pending rows increment a private check counter under the coordination locks so an old pending report cannot starve newer ready reports. The counter does not change public subscription state. Commands, capture and official deletion share the recovery coordination fence. Report authority comes from the existing query repository/service and is rechecked at capture. Cancellation only cancels the additional request. The processed outbox capture records no recipient email, birth fields or report prose and cannot be mistaken for sent delivery. An existing automatic `report-ready-email:{version}:{owner}` delivery suppresses an additional capture. Capture uses a separate outbox key, avoiding a collision with PDF publication's automatic delivery insert.
